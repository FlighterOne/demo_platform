# demo_platform: платформа для курсов

```
main.go       бэкенд одним файлом (Go, только стандартная библиотека, внешних пакетов нет)
go.mod        модуль Go
Dockerfile    сборка для Amvera
index.html    весь сайт для клиентов одним файлом (выкладывается на GitHub Pages)
data/         база: data/db.json создаётся сама при первом запуске
run_local.bat запуск у себя на компьютере
```

## Как это устроено

```
Клиент → https://ваш-логин.github.io/... (index.html)
            │  fetch по HTTPS, JSON, токен в заголовке Authorization
            ▼
         https://ваш-проект.amvera.io/api/...  (main.go)  →  /data/db.json
```

## Локальный запуск

1. Установите Go: https://go.dev/dl/
2. Дважды щёлкните `run_local.bat`. Откроется http://localhost:8080, бэкенд сам отдаёт index.html.
3. Войдите как `admin@local.test` / `admin12345` (меняется в `run_local.bat`).

## Выкладка бэкенда на Amvera

1. Создайте приложение в Amvera и загрузите в него `main.go`, `go.mod`, `Dockerfile` (через git push в репозиторий Amvera или привязку GitHub). Amvera сама найдёт Dockerfile и соберёт приложение.
2. В настройках приложения проверьте: порт контейнера **80**, постоянное хранилище смонтировано в **/data** (там будет база).
3. Добавьте переменные окружения:
   - `ADMIN_EMAIL` и `ADMIN_PASSWORD` (от 8 символов): админ создастся при первом запуске. После первого входа пароль можно сменить на сайте, а переменную `ADMIN_PASSWORD` удалить.
   - `ALLOWED_ORIGINS=https://ваш-логин.github.io`: только с этого адреса браузер сможет обращаться к API.
4. Включите домен приложения (вида `https://имя-проекта-логин.amvera.io`) и проверьте `https://.../api/health`, ответ должен быть `{"ok":true}`.

## Выкладка сайта на GitHub

1. В `index.html` в самом верху поменяйте `window.API_URL` на адрес приложения Amvera (обязательно `https://`).
2. Залейте `index.html` в репозиторий и включите GitHub Pages (Settings → Pages → Deploy from branch).
3. Папку `data/` в GitHub не заливайте: в ней ученики и хэши паролей. `.gitignore` это уже учитывает.

## Безопасность

- **Шифрование трафика:** весь обмен идёт по HTTPS (TLS), и на GitHub Pages, и на домене Amvera. Сайт отказывается отправлять запросы на адрес без `https://`. Бэкенд с `FORCE_HTTPS=1` отклоняет незашифрованные запросы и шлёт заголовок HSTS, который запрещает браузеру ходить к API по HTTP.
- **Пароли** хранятся только как хэш PBKDF2-SHA256 (120 000 итераций, своя соль у каждого).
- **Вход:** случайный токен на 30 дней. В базе хранится только его SHA-256, так что утечка базы не даёт войти. После смены пароля, сброса или отключения ученика все его старые входы закрываются.
- **Защита от перебора:** не больше 10 попыток входа с одного IP за 15 минут и не больше 5 заявок в час. В форме заявки есть ловушка для ботов.
- **CORS:** запросы принимаются только с адресов из `ALLOWED_ORIGINS`.
- **Доступ к урокам** проверяет сервер: текст и видео платного урока без доступа не уходят в браузер вообще.
- Админ создаётся только из переменных окружения, поэтому захватить админку через сайт нельзя.

Видео не хранится на платформе, плеер встраивается по ссылке. Для платных уроков ставьте видео «по ссылке» или приватным, а надёжнее всего используйте Kinescope с ограничением по домену.

## API (для справки)

Публичные: `GET /api/public`, `GET /api/lessons/{id}`, `POST /api/leads`, `POST /api/login`, `POST /api/logout`.
Ученик: `GET /api/me`, `POST /api/me/password`.
Админ: `GET /api/admin/data`, `POST /api/admin/courses|lessons|users`, `DELETE /api/admin/courses|lessons|users|leads/{id}`, `POST /api/admin/users/{id}/reset`, `POST /api/admin/leads/{id}`, `PUT /api/admin/settings`.
